# 单车救急的封锁局短窗验证

QQ-v6 和 Master7sE 的两场公开回放均为 QQ 在席1。败局比赛记录种子为157458776，裁判配置种子为1331727176；胜局对应1941966395与397168106。原裁判逐帧重现两局全部600个状态，分别从40、60、90、164步恢复并核对各35步的历史动作结果。真实败局第90和164步，我方分别有4和3名工人，0棵树，现金均为7.53。

每个起点比较固定随机流的冻结QQ-v6根策略和加上 `breakout.py` 的同策略。每次允许改一名采集员动作，入库基地同回合要招人时也可撤回招募。双方在分叉前使用本席合法观测和自己实际执行的历史动作预热，干预拿到冻结策略的根动作概率和对手预测。活动对手为已公开的同系列 Master3s2；双方均只执行根决策，前向搜索预算为0。开环对照按真实 Master7sE 的已录动作施压；它不随我方改变作出反应。新工人须在同一步、同位置以同职业出生才继续接受历史命令，否则停留。第90、164步的两条开环实验路径均没有未匹配的对手工人；第40步有94至102个未匹配工人回合。

在历史获胜局的8个控制配对中，逐步计算的救急动作都与基线相同。最明确的局面是败局第90步，干预同时改善两个对手模式下的20和35步交付及现金。到第164步时，在两类对手面前仍可加快首20步的交付，35步后的效果已经分歧。四个起点的观察窗口部分重叠，所有结论只覆盖这两个地图和单一根策略随机流。

两张图均配置 `smeltCost=0`。撞在自家基地时，唯一最轻的采集员吸收死车货物后会将全部货物交给基地所有者，包括敌方采集员赢得碰撞的情况。最轻载货平手会使工人全灭，货物在碰撞阶段直接记到基地所有者的现金里。在相邻格被截击则不会自动记入基地。

验证用 `PYTHONHASHSEED=0 nice -n 15 python experiments/v7/branch_breakout.py`，资源为单核。冻结干预 SHA-256 为 `31d69d74bcfe28ea08d509bad919165678808a9c1203bdcb93a43fc23e3154d2`。仓库附带两场已清理的公开回放输入，完整结果在 `branch-breakout.json`，包括双方各窗实际现金、入库、存活工人、树、在途碳、死亡和修改过的工人动作时点。
