# 一名采集员自筹补员款的开发图结果

冻结QQ-v6根策略在四张预定开发图上双方换边，双方每步重新决策，关闭前向搜索。该规则要求预期现金不足以补充一名工人，并且最近采矿或收款明显落后，才尝试派一名空车或轻车在距基地1至4格的安全矿点采2至3次并返库。

**八个席位视角均没有触发分配。** 全部299步动作与原策略相同，最终4胜4负，席0与席1各2胜。每局到第20、60、100、200、299步的双方现金均与此前独立归档的基线一致。四场基线完整模拟时逐步影子计算两席的候选动作，确定整个干预窗口没有出现首个不同指令，故复用相同轨迹作为对应对照。

| 第5至155步依次加上的条件 | 剩余席位回合 |
| --- | ---: |
| 四图两席全部观察 | 1208 |
| 当前现金低于30 | 157 |
| 同时少于8名工人 | 133 |
| 计入约4步现有树收入仍不够 | 81 |
| 没有能够直接回库解决问题的近距离载荷 | 50 |
| 再计入冻结模型预测的5步入库仍不够 | 21 |
| 近期采收、入库或预计收款还明显落后 | 0 |

因此，零触发的瓶颈出现在经济落后条件，数据还没有检验富矿是否安全、能否送回、能否多招到人。一个单独的合成可见局面能触发连续两步停采，再向自家基地走两步，资金充足后解除。它仅检查规则是否可执行。该版本留作未证实收益的实验。

复核用 `PYTHONHASHSEED=0 nice -n 15 python experiments/v7/income_loop_probe.py`。结果文件 `income-loop-probe.json` 保存四场每个观测点的双方现金、实际入库、采矿、招募及树，和八个席位与控制的差值。
