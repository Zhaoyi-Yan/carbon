# v9 上线后的冠军回放研究：先验证响应式开局，再决定如何学冠军

日期：2026-11-25（香港时间 / UTC+8）。仓库审查基点 `6394f15d3317348b8682a35ec68b98f54487aff9`；v9 本地文件来自 `experiment/v8-own-prior` 的 `e97a386b290a1727f26331470094ab57cd452948`。本报告只做回放分析和局部代码路径验证，没有训练、运行新对局或上传比赛策略。

## 结论与当前执行优先级

**研究第一名是对的，但“把冠军数据再训练一遍”还没有说明要修复什么。** 这次实际分析了同一 Artemis 策略 ID 的 **28 场完整回放**，其中 12 场来自最新窗口、16 场从历史快照恢复；保留全部败局。我们已经能提出一个具体、便宜、可被否定的改动，以及一条有明确区别的后续学习方向。

1. **v9 对强敌尚无明显突破。** 11 月 25 日 10:59 的官方导出快照记录 v9 总计 30 局、16 胜，其中对当前前六 8 局、1 胜，平均终局分差 −731.13。不能用这批非配对线上成绩取消上一轮“对冻结 v8 本地验收通过”的结论，也不能把本地通过扩展成已接近前六。
2. **最明确、可直接落到代码的冠军差异是开局。** Artemis 28/28 局首步 `{}`；v9 30/30 局立即招募一采一种。v9 已有先观察的 `_r6_opening()`，但其返回值被随后执行的 `_v7_early_income()` 覆盖。
3. **主要经济差距值得看持续资产经营，而非只看现金、人数或一次种树。** v9 对前六早期人数并不少，但拥有树的累计回合数少约 20.1%；扣除种植、夺树支出后的树收入账差平均 −485.78。这个账差是观察性分解，不能当作“多种树能提高 486 分”的因果收益。
4. **下一步只执行一个固定候选：从冻结 v9 恢复现有的一步响应式开局。** 最多 12 图初筛 + 12 图独立确认、每图换边，合计上限 48 局；失败即结束这条候选。本次不启动大规模重训，不扩张等待时长/职业组合矩阵。
5. **若之后投入学习，应改变可学习的决策范围。** 训练能生成基地招募和工人配合的完整队伍候选，并核对最终执行路径，而不是再拟合当前仅作用于工人的 56 个 prior 参数。v8 以前已经用过同一 Artemis 的 34 场数据，不能把重跑旧配方称为首次学习冠军。

下面严格区分直接观察、代码事实与待验证的解释。完整原始回放、校验清单和复算程序随本报告保存，Codex 不必依赖会滚动覆盖的上游窗口。

### 2.2 不是简单的“人招少了”

以下为这 8 场比赛的同场双方均值，t 为执行到该状态的回合数。

| 指标 | v9 | 对手 |
| --- | ---: | ---: |
| t25 工人总数 | 6.750 | 5.875 |
| t50 工人总数 | 9.625 | 9.500 |
| t100 种植者数 | 2.750 | 2.500 |
| 累计拥有树回合 | 1235.25 | 1545.38 |
| 记录的树吸收收入 | 2790.19 | 3560.02 |
| 每个拥有树回合的收入 | 2.259 | 2.304 |
| 成功新种树数 | 26.875 | 31.125 |
| 成功夺树次数 | 24.000 | 23.125 |
| 终局未入库货物 | 16.16 | 72.51 |

“拥有树回合”是状态 1 至终局每回合归己方的存活树数之和，一棵树归己方 20 回合计 20。它同时受种植时间、拥有多少树、被夺/夺回以及生命周期影响，不等于单树寿命或“防守能力”的直接度量。表中树收入/树回合使用总量之比。

在本样本中，树收入少约 21.6%，其中拥有树回合少约 20.1%，单位回合收入只少约 1.9%。**直接观察支持优先追踪什么时候建立和失去产出资产；不支持直接加种植者数量或夺树奖励。** 人数、夺树次数本来就没有同方向的缺口。

按回放及已读裁判规则重建支出：

`树净现金 = 记录的树吸收收入 − 种树支出 − 夺树支出`

v9 相对对手的树净现金均差为 **−485.78**，8 场中 7 场为负；其他现金流残差均差 **−279.10**，较少招募支出带来 **+33.75**，合为终局 **−731.13**。其他现金流残差含实际入库、碰撞直接支付及舍入，**不能标成纯采集收入或实际入库收入**。种植支出按裁判回合初定价、旧树数保护阈值和枯萎/新种 ID 时序重建，未逐回合重跑裁判；指标定义见 [metrics.json](v9-leader-study-20261125/metrics.json)。

这些是实际路径的会计分解。增加一棵树会改变价格、路线、碰撞和敌方反应，因此不能将 −485.78 当作可直接回收的收益。上一轮持续树任务、回本筛选以及联合种树候选已经出现“局部更漂亮、终局更差”；[旧实验总结](yan-v8-next-experiments-20261124.md)中的持续树控制均差 −211.76、20 步现金改善而终局 −54.51，都要求我们保留这个边界。

### 3.2 冠军的优势不是“开局就所有指标领先”

上述对 Ryan960 的胜局里，Artemis t30 **0 棵树，对手 3 棵**；到 t75 变成 **8 对 4**，现金差 +137.65，货物差 +82.81，最终 +904.26。反过来，败局 t75 也是 **8 对 5 棵树**，但现金差 −954.74、现金加货物仍差 −786.76，最终 −1439.20。

所以既不能把 t30 树少判成已输，也不能把 t75 树多判成经营更好。值得从示范中学习的是**招募、生产、路线与争夺之间的时序和配合**，而不是给某个截面的树数设置硬目标。这两局只是例子，不是已识别的冠军规则。[历史逐局阶段数据](v9-leader-study-20261125/history_metrics.json)

## 4. 为什么现有训练未必能学到这些差异

### 4.1 v8 已经学过冠军，v9 这轮则只改了有限接口

旧 [elite-refit 来源][elite-report]有 494 局、494 个布局，其中 **34 局为本次同一 Artemis ID**；还有 134 局 Apollo、40 局 Master7sE 等。旧训练包含基地动作标签，不能说它从未见过开局。当前恢复的 16 场就是这 34 场中的一部分。

原先“只混前六 / 前六再加一些其他教师”的候选也没有显示稳定优势；最后形成 v8 的实验依赖完整系统消融与独立确认。数据教师更多、动作交叉熵更低、局部树行为更像高手，都不能自动替代完整对战。[历史教师清单][elite-teachers] · [v8 完整系统消融][elite-ablation]

v9 的 own-prior 与这轮全网络 refit 是两件事。v9 只替换 `_V7_OWN_COEF` 的 54 个系数和 `_V7_OWN_SCALE` 的 2 个尺度，给已有搜索增加/改变一个工人动作候选；本轮拟合还跳过前 10 步。在候选生成中，基地 logits 被锁到 `act0`。因此，**即使给这个接口更多冠军回放，它也不能直接学习改变基地招募，更不能从被跳过的开局样本学习首步等待**。[v9 拟合代码][prior-fit] · [冻结 v9 文件][v9-file]

这不否定 v9 通过过本地验收，而是解释为什么该增量不应被期望重塑整个策略。

### 4.2 已有响应式开局在最终执行前被覆盖

冻结 v9 的最终动作处理顺序是：

```python
act = _r6_opening(obs, configuration, lb, act)
if configuration is not None:
    act = _v7_early_income(obs, configuration, lb, act)
st['tr'].set_actions(players, act)
```

`_R6_OPENING = 'react'` 时，`_r6_opening` 在 step=0 返回 `{}`，随后观察对方工人再确定一采一种的位置；但 `_v7_early_income` 在 step=0 又无条件输出一采一种。后者只在 step=0 起作用。

我对 30 场 v9 的真实初始合法观测做了局部调用核对：现有响应式函数均返回等待，后续函数均恢复一采一种，与回放首步职业数量一致。另对双方仍无工人的 step=1 状态核对，响应式函数会招募，不会等待对手无限空过。这里使用零基地 logits，验证的是调用覆盖和职业数量，**没有执行完整策略推理、复现具体基地分配或证明棋力**。[探针](v9-leader-study-20261125/opening_override_probe.py) · [结果与限制](v9-leader-study-20261125/opening_override.json)

不能把覆盖直接定性为 bug。它是 v7 时有意加入的更早启动规则，曾在 4 张开发图、8 局无搜索对照中取得 6–2；同阶段的职业位置优化后来独立验证为负，恰好说明开局规则很容易过拟合。这是重新验证旧取舍的理由，而不是直接宣布删除后一定更强。[旧 v7 开局实验][v7-opening]

## 5. 给 Codex 的唯一立即实验：恢复现有一步响应式开局

### 5.1 固定问题、基线和候选

**问题：在完整 v9 中，恢复已有一步观察及其职业位置响应，能否优于立即一采一种？** 这是一个完整开局规则的比较，不把结果单独归因于等待时间或位置选择。

从下列固定文件建立独立实验分支（建议名 `experiment/v9-reactive-opening`）：

| 项目 | 固定标识 |
| --- | --- |
| 当前部署名称 | yan-QQ-v9，策略 ID `0f9896ed3dc3cd7bfad29fe2dd38d6fb` |
| 本地冻结来源 | `e97a386b290a1727f26331470094ab57cd452948:yan-v8-own-prior.py` |
| 本地基线 SHA-256 | `83bc00ca52ba42ece876830649c9bc488105e763179b62018558f555bb94fa9c` |
| 唯一策略变更 | 删除 `_act()` 中对 `_v7_early_income()` 的调用；保留函数定义和其余源码 |
| 保持固定 | 网络、prior 参数、搜索和对手模型、评分、候选预算、后处理其余部分 |

该候选正常初始条件下只空过一步；即使对方也空过，step=1 仍招募。它没有复刻冠军的全部开局，也不测试连续等两步或等到对方先动。**运行对局前固定候选 SHA、完整 diff、screen/confirm 地图与实际初始布局 SHA，并提交实验协议。** 后续局面会因开局不同而改变，这是预期的因果路径，不能把“仅一行改动”说成后续动作不变。

先做必要的执行检查：完整候选在合法初始观测返回 `{}`，step=1 合法招募；历史追踪保存最终执行动作；策略正常加载、运行预算未变。若不能满足，停止并报告实现问题，不以静默 fallback 空动作计作有效策略。

### 5.2 有上限的评测与停止条件

沿用上一轮效用：

`U = 0.5 × sign(候选终局现金 − 基线终局现金) + 0.5 × tanh((候选终局现金 − 基线终局现金) / 1500)`

| 阶段 | 预算 | 预定判断 |
| --- | --- | --- |
| 初筛 | 12 张新图 × 2 席 = 24 局 | 平均 U > 0，双方正常结束，候选无运行故障，才进入确认 |
| 独立确认 | 另 12 张新图 × 2 席 = 24 局 | 同一 SHA；平均 U > 0 且 95% 地图 bootstrap 区间下界 > 0，才称本轮本地通过 |
| 未通过 | 任一阶段未满足 | 保留所有胜负与原因，结束本候选；不补第三批，不扫等待时长，不调整 CP/PC 再沿用旧确认集 |

地图两席一起重采样；固定 RNG `20261125`、1,000,000 次 percentile bootstrap、双侧 2.5%/97.5% 分位，与上一轮复算口径一致。两阶段候选、对手与裁判版本保持相同。使用完整终局，不用 20 步现金或树数代替主效用。两批地图应与开发、旧训练/留出、旧 v7/v8 对战的已知布局清单核对；检查实际布局而不只检查 seed 数字。对无法恢复的历史输入只报告可核对的隔离范围，不声称排除了全部未知历史重叠。

逐局记录胜负、分差、席位、两侧 SHA、地图/布局、正常结束状态、超时/异常、实际首步动作。合并结果、席位差异和树回合只作解释，不增加事后通过条件，也不依照席位结果拼接新版本。故障局不能计为策略胜利或悄悄删除；本轮有故障先停止并记录，不以修正版继承本轮确认资格。

**这是最多 48 局的研发预算，不是保证足够功效的样本量。** 未通过表示该候选在本预算内没有达标，不能证明所有响应式开局都无用；但本轮仍停止。冻结 v9 仅提供立即混合招募这一类对手，未覆盖冠军镜像等待、双采首发等开局。因此通过也仅支持“对冻结 v9 有局部改善证据”，不能推算对前六胜率。比赛平台是否评测由维护者决定；这次不自动上传。

## 6. 如果继续训练，怎样才与已失败/已完成的路线不同

**当前不并行启动此分支。** 开局验证的收益可能有限，树资产和队伍配合才是更宽的能力问题；如果之后要投入训练，我建议只推进下面这个方向：**把完整 v9 保留下来，学习一个能表达队伍配合与基地动作的冠军示范候选。** 不从弱化的 Zero 起点重学整个游戏，不把未知的冠军内部算法当作前提。

### 6.1 数据单位从“更多强者动作”变成“可执行的队伍决策”

- 按精确策略 ID 分教师与版本；当前目标为本报告第一名 Artemis，不先混前十。保留输局、未种树/未夺树的时刻和双方互动，不能只截胜局的成功种树事件。
- 使用整回合的基地与工人动作；显式保留开局 t0–9。按开局、扩张、争夺、兑现阶段平衡采样，让关键决策不被大量普通移动稀释。旧 full refit 也有开局和基地标签，区别必须体现在采样、建模和最终执行路径上，不能仅改数据集名字。
- 以地图划分训练、开发和保留集；历史 16 场已有训练来源，当前 12 场也已被本报告用于发现假说，不能再宣传为完全未见的最终验证。最终收益仍需新地图完整对战。
- 输入限定为当时合法观测及可重建的过去历史。回放 `full_carbon` 可用于初始布局核对，不能进入策略特征；未来收益可作离线分析/标签，不能作为决策输入。

### 6.2 必须允许学到的动作真正执行

当前 worker-only prior 固定基地动作，且最后还有手写覆盖。新候选至少要联合提出工人行动及基地招募，并共同满足资金、人数和冲突约束；保留一个完整队伍候选，避免将多个教师的逐工人边际概率随意拼成互相冲突的队伍。

训练前先在已归档开局和争夺样本上检查：目标动作是否在模型输出空间内，是否能穿过解码、搜索候选选择接口和最后后处理。报告目标动作覆盖率和被改写的原因；**后处理继续强制抹掉的行为，不值得先花训练成本拟合**。这项检查不能用“logits 更像老师”替代。

冻结原 v9 的搜索/价值体系，先把新的联合候选放进固定预算。若候选能被表示却持续被评分拒绝，先报告是“未生成、未被选中、还是执行前被改写”，不要同时更换 critic、加树奖励和扩大搜索，将原因混在一起。当前评分审查在不同局面中既看到 tail 有害也看到 tail 有益；增加一类敌方回应在独立样本恢复过碰撞，却未改变最终动作，仍不足以支持直接删除 tail 或大范围扩回复。[评分审查][score-audit]

这条路径的预期作用是让搜索看到以前接口无法提出的整套行为；它可能因离线分布偏移、候选预算或评分不足失败，不能保证只靠模仿就超过老师。champion 私有源码不在手，我们只能使用静态示范，不能承诺让冠军对我们新局面在线打标签或开展 DAgger 式交互。

### 6.3 是否值得继续，应由完整系统收益判断

教师动作准确率、基地选择准确率、关键阶段的可执行候选覆盖率用于解释模型究竟学到了什么；真正采用仍要挑战当时已验证的完整主力，再看新线上跨对手结果。**本节是有条件的后续设计，不是同时派给 Codex 的第二轮实验。** 当前先完成第 5 节这个低成本、单候选验证；失败时不要把扩大训练当作自动补救。
