# Carbon-Zero Zero-W 首轮本地试点

2026-11-24。基于 `2603665` 的 [研究计划](../carbon-zero-research-plan-20261124.md)。训练种子 24000000。协议、逐局结果、优化日志和权重摘要与本报告一同归档。

## 固定起点与对照

- W-raw 复用了 Claude 本地实际 `cand_ft3.py` 的 Apollo 风格（第 122 行），关闭搜索并保留原始冲突处理、招募和末盘回库逻辑。Claude 的存档显示这套配置以前对原网络 16 胜 0 负。原始权重、源码和对局记录的 SHA-256 见 [provenance.json](provenance.json)。
- ZW0 保留同一权重和风格，使用固定排序的顺序解码器。先采样基地招募，再按工人 ID 顺序逐个采样，有不冲突的合法选项时排除已有队友预订的目的地。温度定为 0.4，初始网络和训练对手都是 ZW0。ZW1 训练全 actor，并使用新 critic 预测混合效用下的回报。
- 训练采用仓库裁判及分别更新的双方合法观测历史。每次裁判同时执行两队指令，训练端只收集 learner 一侧，因而 E 等于 L。新目标混合本地胜负和有界分差各一半，并用公开现金差的势函数做过程奖励。平台公开确认两者等权，软分的具体公式仍未公开。[官方策略说明](https://117.72.210.134/static/agent-guide.md)
- P 使用相同的温度和顺序解码器。两组纯策略分别和冻结 ft3 generic、关闭搜索的 v6 在同图同席位对照。S 使用 ft3 自带的旧搜索及其原生解码，只替换自己的根节点 logits，保留旧价值、对手和续局网络。S0 和 S1 分别和完整冻结 v8 换边跑。两个模式各自对比自己的冻结分支。
- 完整 v8 使用 `v11-yan-v8-elite-refit`，v6 来源是 `v9-yan-v6-estuary`。完整搜索按竞技场真实单步限时运行，旧搜索会按墙钟预算调节宽度。纯策略与搜索测试使用开发图，每对手每个检查点分别为两图或一图换边。独立晋级复核仍需另开地图。

## 工程验证

- 初始 PyTorch 网络与 NumPy teacher 的 worker/base logits 逐头一致。检查了两席、历史特征、隐藏碳变化下输入不变、已采样命令的 old logprob 重算、势函数求和、GAE 和中断窗口恢复。
- Ryanx 快引擎在 100 个随机完整或提前淘汰的轨迹中逐步比对 19,397 次，又在 24 局历史搜索对战中通过 7,176 次逐步比较。双方资产、树、完整碳图及 ID 计数与参考一致。独立的观测、裁判状态/奖励接口和手工边界状态仍待验证。本轮采样使用仓库裁判。
- 早期独立解码器同图换边对 W-raw 0 胜 6 负，平均分差 −1672。顺序解码器为 1 胜 5 负、平均 −680。独立解码器的预跑在完成 10k 检查点后结束，训练结果单独留档。后面把顺序解码固定给 ZW0、ZW1 和固定训练对手，避免把更换解码器的收益算给 PPO。

## 温度与训练曲线

冻结权重、地图和解码器，顺序解码下 T=0.4 对 T=1.0 打出 8 胜 0 负，平均分差 +1615。固定 T=0.4 后，ZW0 在另一组两图换边中对原生 W-raw 1 胜 3 负，平均 −222。顺序解码器仍留下了可测的棋力缺口。

| 训练步 E | 对冻结 ZW0 胜–平–负 | 平均分差 | 混合效用均值 | 0/1 号位胜场 |
| ---: | ---: | ---: | ---: | ---: |
| 10,000 | 1–0–7 | −445 | −0.497 | 0 / 1 |
| 100,000 | 3–0–5 | −701 | −0.296 | 2 / 1 |
| 200,000 | 0–0–8 | −2362 | −0.954 | 0 / 0 |

三次都使用同一组四张新图换边。200k 对 ZW0 的八局全部正常完赛。训练本身完成 668 局，其中 656 局走满，12 局由裁判提前淘汰。两席各完成 334 局。主跑 MPS 两线程，采样 14.4 分钟、优化 11.4 分钟，合计约 25.9 分钟，端到端约 129 E/s。采样按计时累计含编码 220 秒、推理与采样 246 秒、裁判 394 秒，共 25,196 次批前向（计入 bootstrap，不含优化器）。

## 策略偏移

[冻结动作分布的诊断](actor-drift.json)在同一批历史实战的合法观察上展开，对 112 个队伍局面固定 ZW0 的采样前缀后比较动作分布。10k、100k、200k 的平均每队 KL 依次为 0.25、2.51、4.58 nats，最可能工人动作变化率约 5%、16%、21%。同期对上一轮行为策略的平均 minibatch KL 约为 0.005–0.007。局部更新很小，连续更新仍能走远。动作分布偏离集中在开局之后，220 步诊断组偏离最大。这与棋力退化同时出现，单凭该诊断不能分辨更新方向、critic 误差或探索分布各自的贡献。

在主跑之后补了一次 [10k 单变量复验](anchored-10000/protocol.json)，损失增加 0.1 倍相对于冻结 ZW0 的条件动作 KL。训练种子、解码器、初始权重、目标、E 与测试图相同。10k 的队伍 KL 从 0.246 降到 0.100，同图直打 ZW0 从 1 胜 7 负、−445 变为 5 胜 3 负、+43。这一批只有四张图。对两个外部对手的配对分差仍为负，对 generic 为 −121，对无搜索 v6 为 −750。这个短复验支持继续分析偏移和训练分布，对外部泛化还没有正证据。

100k 搜索接力曾留下一半结果。恢复评测保留原 S0 的两局，补跑 S1，重算纯策略配对。100k 和 200k 的八局 S 都走满 299 步。最慢单步 0.924 秒，双方超时与错误均为零。两轮完整搜索各约 10.5 分钟，两席并行，冻结与学习臂分开启动。200k 在 0 号位记录到 S0 有 298 步搜索完成，S1 有 140 步。旧搜索的候选去重和耗时预算会影响完成次数，现有记录不足以拆分两者对差距的贡献。

纯策略 NumPy 导出约 5.54 MB。旧搜索诊断导出约 11.18 MB，同时包含冻结网络与学习网络，超过平台的 10 MB 上限。[官方策略说明](https://117.72.210.134/static/agent-guide.md)

## 决定与归档

继续使用 yan-v8。主跑和单变量复验都保留在实验分支。200k 对同解码器冻结基线、两类纯策略外部对手和完整 v8 的根策略迁移均出现退步。冻结策略 KL 约束减轻了短期偏移，外部对照仍为负，当前证据不足以扩大训练预算。搜索迁移每检查点仅用一张图，这部分主要验证接口和识别明显退步。

`external-*.json.gz` 包含完整搜索的原始指令及每步现金；同名 JSON 为便于查看的精简记录。训练日志、逐局结果、原始胜负和导出校验值均与实验代码一同存档。生成的权重和 Python 导出保存在本机 `arena-runs/carbon-zero-20261124`，见 [artifact-hashes.json](artifact-hashes.json)。复现需要 [来源清单](provenance.json) 指定的本地 ft3 文件。
