# Carbon 路线调整：暂停当前 Zero 配方，回到完整 v8 的能力上改进

> **执行结果更新（2026-11-25）：** `e97a386` 已完成下述单一 own-prior 候选与两批共 48 局，独立确认通过原定门槛。见[最新复审与交付结论](v8-own-prior-review-20261125.md)。冻结候选并结束本轮开发，不追加第三批 v8 对战或重新拟合；Zero 继续暂停。以下保留为事前协议。

日期：2026-11-25（北京时间）。最新实验快照：**`e8a4151825b79d793b14cad85463765ba2aec9b3`**。用户明确提出两个问题：为何连续实验仍没有可用增益，以及目前纯策略离完整 yan-v8、前六名是否太远。

**决策：暂停当前 M/G/M-wide 训练，不追加 wide 第二种子、40 图确认或百万步长训。近期目标恢复为“产生一个在完整 v8 上有实战增益的候选”。下一轮只允许一个有总预算的尝试：用完整 v8 的最终动作更新其已有工人候选 prior，接回完整 v8，并直接挑战冻结 v8。**

这不是已找到突破前六的算法。它明确保留现有系统能力，停止以“弱纯策略之间有差别”代替发布版本的进展。独立端到端 RL 仍可能有效，但目前应视为单独的长期研究选项，不作为近期赶上 v8 的默认路径。本文替代 [上一轮 M-wide 交接](carbon-zero-mg-review-20261125.md) 的下一步安排；全部历史负结果保留。

在同一新面板中，对手仍是**关闭搜索的 v6**：

| M seed 1 | 7–0–17 | −618 |

这不是接近完整v8或前六的证据。**当前M/G没有对完整v8的直接比赛，因此不能编造具体M-v8胜率或Elo差距。** 但现有评估已经说明，继续围绕ZW0附近的小变化，不能替代用户真正关心的目标。[原始面板][panel]

### 2.1 当前 Zero 并没有继承完整 v8

| 部分 | 当前 Zero | 完整 v8 |
| --- | --- | --- |
| 初始化 | ft3 Apollo固定style 122 | 自身权重、多风格路由及历史模块 |
| 实际出招 | 网络＋固定ID顺序避冲突解码 | 原生解码、冲突/招募/回库处理 |
| 规划 | 当前M/G评估不搜索 | 多个联合候选、对手回应、价值与尾部评价 |
| 搜索后处理 | 不包含v8整套逻辑 | 现金路线、短程入库、走廊、偿付和开局处理 |
| 训练对手 | 100%冻结ZW0 | 当前部署能力需直接对完整v8评估 |

这意味着新路线承担了“先重新学回被移除的能力，再尝试超过现有系统”的任务。保存一个强网络的权重，并不等于保存强系统的行动策略。[Zero导出][export] · [v8实际策略][v8]

更具体的证据：

1. 原首轮记录中，ZW0与原生W-raw使用同一网络，但换解码后，早期3图换边为1胜5负、均差−680；固定温度后的另2图为1胜3负、均差−222。W-raw本身也关闭搜索，但保留原冲突、招募和末盘回库逻辑。样本小，不能据此精确量化解码损失，却说明能力变化在RL训练之前已经发生。[首轮报告][pilot]
2. v8根解码允许部分满员工退休碰撞，以及末盘同基地collector重叠。Zero的occupancy mask在有其它可选动作时会排除已被预订的落点；部分v8动作组合在这一解码下无法选择。这里是实际策略约束的差异，不只是“参数还没训练好”。[v8策略][v8] · [Zero解码][policy]
3. 早期所谓搜索迁移是“ft3旧搜索＋替换root logits”，不是“完整v8＋新网络”；当前export的精确字符串替换也不能直接适配v8的`_v5_root(...)`入口。不能把旧的少量S0/S1对局当作当前M对v8的实测。[导出实现][export] · [首轮报告][pilot]

## 3. 为什么之前越来越麻烦：需要改的是推进方式

前期修正终局、概率、critic冻结和诊断广播等问题有必要。但后续安排过多地围绕短跑、小面板、估计器细节推进，缺少对“完整发布策略是否在变强”的连续交付。这部分应由研究计划承担责任，不能简单归结为Codex实现慢。

每次约50k E实际只有11批、176局、约107–109次optimizer更新，不是5万次梯度更新。本mg目录的五个主跑总计259,620 E、880局。已记录的训练采集与优化小计约半小时量级，尚不含全部baseline、I/O和评估；反复人工解释、切换方案的成本已经很突出。[资源复算](carbon-route-reset-20261125/statistics.json)

这些短跑足以决定某个配置暂不值得扩大，却不足以证明整个RL方向不可能。另一方面，直接扩大为百万步，也没有证据保证能追回被移除的v8能力。当前训练只针对ZW0，跨对手宏指标又在检验泛化；两种问题混在一起，也增加了解读难度。

**现在的执行原则：每次只交付一个固定候选，部署验收直接对完整v8负责。** 不再把每次几分钟的短训练、一个不稳定的小正号和一篇新文档当作一次棋力进展。保留已验证的环境、轨迹、导出和评测代码；当前Zero训练配置归档。

## 4. 下一轮只做一个有限尝试：更新 v8 已有的候选 prior

### 4.1 为什么选择这个接口

仓库已有 `experiments/v7/own_search_fit.py` 和 `own_search_prior.py`，v8仍保留它们产生的工人联合候选入口。旧模型学习的是冻结**v6**最终执行的动作，按职业做轻量线性修正；它不是完整v8蒸馏。历史拟合使用48张训练图、26,692个工人标签，另16图留出；该单组件的离线改善较小，不能把整套v7后来的资格成绩全归因于它。[历史记录][ownreport] · [拟合入口][ownfit] · [候选接口][ownprior]

下一轮只检验：**用当前完整v8的最终动作，更新这个已有候选模型，能否在同样搜索预算下帮助完整v8出招。** 模型族与拟合方法沿用原版本，暂不同时换MLP、加大网络、重训critic或加入PPO。

这是一项靠近现有部署能力的小预算尝试，不包装成全新突破，也不声称能把整个v8压缩到一个纯网络。搜索与策略学习相互提供训练信号，是可参考的长期机制；在Carbon上是否有效仍要实测。[Expert Iteration原论文][exit]

### 4.2 一次执行包的范围和预算

**固定发布基线：**`v11-yan-v8-elite-refit`，`submission.py` SHA-256：

```text
a87f8e6b83656c771cb5a25d6b6f383b245127e7c782e4c6c7c4a0a2cc15d396
```

1. **数据。** 优先复用可核对上述v8版本的已有完整对局。标签取最终实际下发动作，包含搜索后的修正；保留胜局和败局。旧v6标签不能改名当v8。最多20,000个可追溯team-state标签，覆盖开中末盘与两席；按布局事先划分训练/留出，比赛地图独立。新生成的教师计算另设4小时累计上限，按所有进程中完整v8教师调用的实际耗时累加，不用并行后的墙钟代替。达到上限不再开启新局，已开局完整结束；报告并行数及收尾造成的超额。有多少可用数据就如实报告，不无限补数据。
2. **拟合。** 复用现有按职业的候选prior及其固定训练配方，只拟合一次、产出一个候选；不进行模型/超参数扫描。用冻结v8的合法观测及真实历史重建特征，不能把仅有最终标签的v8轨迹配上旧lifeline/v6状态处理冒充一致输入。留出NLL用于检查学习是否发生，不能代替对局结果。
3. **接入。** 替换v8已有own-search prior的模型参数/槽位，保留完整v8的其余出招路径、原生解码、原root招募和锁定工人。候选数上限、搜索配置及真实单步限时不增加。用v8专用接入口，验证新候选确实被使用；不要直接套用Zero的ft3 root字符串替换。
4. **实战。** 同一冻结候选对完整v8，在预先确定的12张新图交换席位，共24局。报告候选视角的平均终局U、WDL、分差、两席及超时；U仍采用已有混合代理，不改目标。如果平均U≤0或出现明确运行故障，归档并停止本次尝试；平均U>0且运行正常，才用同一文件再跑另12张独立新图、24局。第二批不重新拟合或挑种子。
5. **结论。** 第一批只用于预算筛选；第二批平均U仍为正且按地图区间下界>0，才认为这个候选有独立确认的改善证据。两批分别报告，不能只合并成功数据；未确认就写未确认，不自动加图或再换一个小变体。本轮最多一个候选、48场正式挑战。比赛平台上传仍由维护者决定。

20,000个新教师调用若接近每次1秒，单进程可达约5.6小时；因此必须优先使用现成轨迹，并执行上述新生成计算上限。不能把纯网络Zero几分钟的训练耗时套到完整搜索教师上。

### 4.3 必须说清的能力边界

- 保留完整v8结构不保证候选不会退化。新prior可能引导旧搜索选错，也可能改变去重和实际搜索深度，必须用完整对局判断。
- 当前v8文件约9.14MB，不能直接再叠加一个4–5MB学生网络。复用已有轻量槽位可以避免为本次尝试额外展开模型压缩工程。
- 完整v8经过搜索和后处理后的动作分布不等于root网络分布。**不能把最终动作直接套进当前纯actor的log-prob继续做PPO。** 本轮是监督学习候选prior，不是已经实现完整系统RL。
- 本接口沿用v8解码，避免要求当前Zero mask表达全部v8联合动作。如果以后做独立神经学生，必须先检查教师动作可表达性，不能静默删掉不兼容标签再声称复制了教师。
- 学习v8候选动作本身不保证超过v8，更不保证击败前六。若本轮不改善，只否定这次有限实现；不再立刻展开新的critic/GAE/地图分配循环。
