# 按对手行为和剩余步数调整打法

实验基线是已提交的 yan-v3。候选仍是一个可独立运行的 Python 文件。当前对手的名称、源码、下一步指令和隐藏碳图都不参与决策。每局第 0 步重新建立对手记录。[策略改动](https://github.com/Zhaoyi-Yan/carbon/commit/ef3c0b3)

- 对手有载碳至少 75 的采集员时，记录原模型预测的“下一格是否更靠近其最近基地”。下一帧若同一个工人仍在场，才用实际位置更新预测偏差。把两格内有更轻的敌对采集员和没有这种压力的样本分开。旧记录每步乘 0.96，用八个零偏差的初始样本抑制小样本波动。调整仅作用于搜索根节点模拟的敌方行动。
- 最后 69 次决策中，按现金差和双方仍可交付的载碳估计领先程度。若同一候选有两种模拟对手应答，领先时提高较差结果的权重，落后时提高较好结果的权重。幅度随领先程度和剩余步数连续变化，只有一个模拟结果时直接使用该结果。
- 若接近终局、预计领先，且载碳至少 75 的工人身旁两格内有更轻的敌方采集员，允许它最多提前六步启程交付。沿用原版对距离、能否按时到家、敌方威胁和己方落点冲突的检查。常规局面继续使用原来的三步余量。

## 上线时能知道什么

官方输入中的 `players` 共享双方资金，以及基地、工人和树木的状态。步数来自 `observation.step`，一局的步数上限来自 `configuration.episodeSteps`；地面碳量仅取观察者的 `carbon`。对手意图是估计量，预测时只能用当前及此前各帧。策略可在单局进程中保存这些观测。[赛事说明](https://117.72.210.134/static/agent-guide.md) · [环境字段](https://github.com/moliqingwa/carbon_challenge/blob/master/zerosum_env/envs/carbon/carbon.json#L192-L313)

例如在归档回放 `226c86a2423236bde1d3bbc06d347866`，将候选的终盘判断应用于 0 号位，第 275 步账面领先 417.3，计入可交付载碳后仍领先约 150.3。第 280 步账面仍领先 331.8，同一估算已落后约 91.9。遇到多个模拟结果时，候选会从偏向守成交付转为愿意承担更多风险。这是对已有局面的回放分析。[原始回放](../replays/top-five/replays/226c86a2423236bde1d3bbc06d347866-1.json.gz)

## 检验方式

将候选冻结为 SHA-256 `709c027befe10e82a40c911e46e9bcf1e9bd76e260a296e9b91e3dcd832a1f4b`。首张图 897419481 上，候选、冻结的 yan-v3 和 Claude 本地最终版三方循环换边，共六局。第二张图 415218647 上，候选与 yan-v3 再换边两局。两张图分别由 ASCII 字符串 `carbon-live-adaptation-first-0` 与 `carbon-live-adaptation-first-1` 的 SHA-256 前四个字节按大端取模十亿得到。Claude 文件 SHA-256 为 `a3d54e4672458e53f5dfd47444b59a25326f5d1592575f968a1a59f26c98b4b0`。原版 yan-v3 为 `ee2b1a51039aaea356e28c6e326d3ec4eb4c06cda054808f068f132447add737`。

另外重放仓库归档的前五选手对局，逐座位、逐帧记录搜索用的原始和调整后的返程预测。每一帧先预测，再到下一帧打分，仅统计下一帧仍可观测的同一工人。Brier 分数是概率与实际 0/1 结果之差的平方的均值，越低越好。这项测试衡量单个方向判断的误差，无法直接推出胜率。[复算脚本](live_adaptation_check.py)

## 实测结果

77 场公开回放的 83,649 次可观察载货工人转移中，有 29,558 次处于轻载对手两格以内。修正后的返程概率绝对变化超过一个百分点的共有 7,918 次。Brier 分数从 0.13183 降至 0.13078，相对降幅约 0.80%，按整场合计 73 场降低、4 场升高。有 242 次工人消失，无法从下一帧位置识别移动方向。这些都没有用于更新或评分。双方合计 45,654 个决策视角中，终盘领先程度高于 +0.18 的有 4,268 个，低于 −0.18 的有 4,268 个。后两项是局面计数，未统计实际有多少次最终走法因此改变。[逐场和逐座位结果](live_adaptation_check.json)
