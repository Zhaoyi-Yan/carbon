复现
  benchmark.py 用原版 zerosum_env Carbon 结算器，独立加载双方策略，并在进程内
  设置地图种子。测试环境为本机 Python 3.13.11 与 NumPy 2.4.2。
  准备原版仓库和表中的三个公开策略文件。将原版仓库根目录放进 PYTHONPATH，
  从本目录运行下列命令（对手文件路径替换成实际路径）。

  PYTHONPATH=/path/to/carbon_challenge python benchmark.py \
    --opponents /path/to/example.py /path/to/juzi.py /path/to/candidate_v3.py \
    --seeds 13 29 47 113 193 257 --jobs 4

  bench 会输出逐局分数、胜平负、单步耗时；有平局或败局时退出码为 1。
  若看到耗时尖峰，可用 --jobs 1 测实际单进程耗时。
  MODEL_TEMPERATURE、MODEL_SEED、BANK_WINDOW、FINAL_SPAWN_CUTOFF 可调。
  后续优化建议保留两组验收局，并以原版 Master2 作为并行对照。

  既有 Master2 改版对 Master3s2 在种子 13 两战全负，平均差 -1,368.28。
  旋转集成版在种子 61 两战全胜，出生位 0 和 1 分差分别 +409.47、+609.42。
  在种子 131、229 独立复测四战全负，平均差 -475.97。对手完成 298–299 次搜索。
  这些是本地完整对战。对手使用下载的原版源码，其采样随机且搜索随实际耗时调整。

  benchmark.py 的 --min-opponent-searches 会检查原版搜索确实启用，并在输出每局比分后
  检查实际完成次数。--progress-every 可将每隔若干步的比分写入日志。
  复测命令（需要原版环境、NumPy 和 PyTorch CPU）如下。

  CARBON_DEBUG=1 PYTHONPATH=/path/to/carbon_challenge python benchmark.py \
    --opponents opponents/claude-AlphaCarbon-Master3s2.py --seeds 131 229 \
    --jobs 2 --min-opponent-searches 250 --progress-every 75
